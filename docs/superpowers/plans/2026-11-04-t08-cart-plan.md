# T08 — Carrito de un evento — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implementar un carrito local temporal para varios tipos de entrada del mismo evento, con cantidades editables, límites visibles y totales provisionales en USD.

**Architecture:** La lógica pura de carrito vivirá en `src/features/checkout/cart.ts`: normalización, límites, subtotal, comisión DEMO redondeada en centavos y serialización segura de un snapshot local. La página de servidor resolverá un evento publicado a partir de los identificadores de la ficha y entregará datos frescos al componente cliente; el componente guardará el snapshot en `localStorage` para sobrevivir recargas y navegación directa. El total mostrado es provisional y T09 lo recalculará con datos del servidor antes de crear la orden.

**Tech Stack:** Next.js 16 App Router, React 19 Client Components, TypeScript estricto, Tailwind CSS 4, Supabase con cliente `anon`, Vitest y Playwright.

**Spec:** `docs/superpowers/specs/2026-11-02-ticketera-design.md`, `docs/superpowers/plans/implementation-backlog.md`, `docs/architecture/SYSTEM.md`, `docs/architecture/DATA.md`, `docs/checkout/DEMO_PAYMENT.md`, `docs/design/DESIGN.md` y `AGENTS.md`.

## Global Constraints

- El carrito contiene un solo evento por orden, pero permite varios tipos de entrada.
- Los montos son enteros en centavos USD; la comisión DEMO sugerida es 5 % y se muestra como supuesto académico, no como política de C3.
- El navegador solo conserva una selección provisional; T09 debe validar en servidor publicación, cupos, límites, precios y comisión.
- No pedir, almacenar ni simular números de tarjeta o credenciales.
- Solo eventos publicados y sus tipos de entrada activos pueden alimentar el carrito fresco.
- La interfaz sigue los tokens C3, español directo, etiqueta DEMO, foco visible, áreas táctiles de 44 px y sin scroll horizontal en 375 px.
- `/carrito/` es privado/no indexable y usa la barra final del proyecto.

## Review Focus

- Snapshot corrupto, de otra versión o con más de un evento: se descarta sin lanzar errores ni mostrar totales manipulados.
- Cantidad no entera, negativa, mayor al cupo o mayor a `max_per_order`: se normaliza o rechaza con un límite derivado de datos del evento.
- Evento publicado que deja de estar disponible o tipo de entrada que se desactiva: la pantalla conserva un mensaje recuperable y no habilita una compra válida.
- Comisión con fracción de centavo: se redondea con una regla estable (`Math.round`) y se mantiene subtotal + comisión = total.
- Navegación directa a `/carrito/` sin query string: se recupera el snapshot local si existe; sin snapshot, se muestra estado vacío accesible.
